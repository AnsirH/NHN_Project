# NAN 2026 게임잼 — 기획 정리 문서 (프로토타입 기준) v4

> 목적: 재미 검증용 프로토타입 개발의 단일 참조 문서.
> 원칙: 이 문서에 없는 기능은 프로토타입에 넣지 않는다.

- **엔진**: Unity (3D)
- **제출 빌드 제약**: 웹(GitHub Pages) 또는 모바일(APK/테스트 링크). **PC exe 금지.**

  - 성능 기준 기기: 중급형 안드로이드 실기 1대 지정, 모든 성능 판단은 실측으로.

## 2. 게임 컨셉

**한 줄 피치**: 장군을 배치해 노멀 병사 부대에 역할을 부여하고, 꽝 부딪히는 대규모 군대 전투를 관람하며 플레이어 스킬로 거드는 3D 전투 관람 게임.

**레퍼런스 (우선순위 순)**:
1. **Mini Warriors** — 최우선 감각 목표. 군대 vs 군대 물량 충돌과 관람의 재미
2. **마인크래프트 점토병사 모드** — 톤앤매너와 롤 부여 감성의 원형
3. TABS / Attack on Toys — 물리 타격감(랙돌, 넉백, 진영 붕괴)
4. Stick War: Legacy — 자동전투 + 플레이어 스킬 개입의 밸런스
5. Art of War: Legions — 모바일 저사양 물량감 연출

**세 개의 기둥**:
1. 군대 vs 군대 물량 스펙터클 (보는 재미가 본체)
2. 플레이어 스킬 개입 (번개, 독구름, 힐 장판 등)
3. **장군을 통한 롤 부여** (정체성 훅: "아무것도 아닌 병사들에게 장군이 역할을 준다")

## 3. 코어 루프 (프로토타입 확정 범위)

```
[전투 전]  3×3 그리드에 장군 배치 → 각 구역 부대의 롤/진형 결정
   ↓
[전투]    자동전투 관람 + 플레이어 스킬 타이밍 개입 (마이크로 조작 없음)
   ↓
[전투 후] 결과 확인 → 다음 전투
```

- **전투 종료 조건**: 한쪽 전멸.
- 전투와 전투를 잇는 **진행 구조(메타 루프)는 미정** — §11 참고. 전투는 독립 모듈로 유지(구현 완료).

## 4. 카메라 (방향 확정)

- **위에서 사선으로 내려다보는 탑다운/쿼터뷰 계열** 시점.
- 함의: 원거리 투사체는 포물선 궤적 / 진형이 한눈에 읽혀야 하므로 롤별 실루엣·색 구분 중요 / **장군은 크기·이펙트로 병사와 즉시 구분**되어야 함.
- 여유 시 검토: 충돌 카메라 쉐이크, 장군 참수·격돌 순간 연출 컷 (프로토타입 범위 외).

## 5. 배치 시스템 (장군 배치) — v3 개편

- 아군 진영 = **3×3 구역 그리드 (확정)**. 구역 1칸 = 분대 1개.
- **장군 1명 = 구역 1칸 = 롤 1종.** 장군을 구역에 배치하면 그 구역 병사 전체가 해당 롤로 변신.
- **장군은 희소 자원**: 보유 장군 수 < 구역 수 (프로토타입: 장군 3~4명 vs 9칸). "어느 부대에 역할을 줄 것인가"가 배치 전략의 본체.
- **장군 없는 구역 = 노멀 병사** (기본 스탯, 최근접 타겟팅). 머릿수 벽으로서의 가치는 있음.
- 장군의 전장 위치 = **해당 분대의 선두** (고정). 함의: 근접 부대 장군은 구조적으로 위험 → 롤별 장군 스탯 차등의 근거 (전사 장군은 튼튼, 궁수 장군은 물몸).
- 규칙은 구역 스냅(이산적), 롤 부여 연출은 오라 파동 등 유기적 표현 허용 — 규칙과 연출의 분리.
- 전투 전 자유 재배치 허용. 상성 카운터는 배율이 아니라 **배치로 푼다**.

## 6. 장군 시스템 — v3 신설

**정의**: 장군은 전장에 실재하는 엘리트 유닛이며, 부대에 롤을 부여하는 캐리어다. 깃발(UI 추상물)의 대체물이 아니라 게임 세계 내 존재.

**능력 구성 — 3계층 가독성 규칙 (설계 철칙, v4 개정)**:

| 계층 | 주체 | 성격 | 빈도 | 가시성 |
|---|---|---|---|---|
| 병사 개성 (이동 패턴·타겟팅·스탯) | 병사 개인 | 질감(texture) | 상시 | 실루엣·움직임 — 소형 이펙트 |
| **장군 액티브 스킬** | 장군→부대 | **사건(event)** | **조건 충전식 — 전투당 2~3회 수준** | 대형 이펙트 — 서사의 축 |
| **장군 패시브** | 장군→부대 | 지속 버프 | 상시 | **비가시 허용** (수치 버프는 안 보여도 되는 유일한 층) |

- **병사는 트리거 기믹을 갖지 않는다 (v4 확정).** 병사 롤의 개성은 이동 패턴 + 타겟팅(위치 필터/우선순위) + 스탯 프로필 세 가지로만 구성 — §7.
- 장군 = 패시브 1개 + 액티브 스킬 1개. (가독성 예산은 개체 수에 반비례 — 장군은 소수·대형이라 2개 감당 가능)
- **액티브 발동 규칙 (v4 확정)**: "전투당 1회" 폐기 → **조건 충전식**. 전투 이벤트(사망/공격/킬/시간 경과)가 게이지를 채우고 임계치 도달 시 자동 발동 후 리셋 (재충전 가능). 전투당 2~3회 수준. 충전 조건·필요량은 데이터 필드.
- 이벤트 희소성 원칙: 부대 스킬이 로테이션처럼 반복되면 사건이 아니라 소음이 된다. 충전 필요량을 "전투당 2~3회"가 유지되도록 튜닝해 희소성을 지킨다.

**장군 액티브 스킬 4종 (확정)**:

| 장군 | 스킬 | 효과 | 충전 조건 |
|---|---|---|---|
| 전사 | 방진 | 부대 전원 K초간 받는 피해 대폭 감소 | 부대원 누적 사망 N명 |
| 궁수 | 일제 사격 | 부대 전원 일제 발사 → 적 최대 밀집 지점 대형 화살비 (광역 데미지) | 부대 누적 공격 N회 |
| 암살자 | 그림자 습격 | 부대 전원 재은신 + 다음 공격 치명타 | 부대 누적 킬 N회 |
| 사냥꾼 | 사냥 선포 | 현재 체력 최고 적에게 표식 → 사냥꾼 부대가 우선 타겟 + 추가 데미지 | 시간 경과 |

- 공통 연출 명세: 발동 순간 짧은 슬로모 + 장군 발광 + 부대 전원 동일 모션 (구현은 뷰 단계에서).
- 사제·광전사 장군의 액티브 스킬은 미확정 (§11).

**사망 규칙 (확정)**:
- 장군 사망 시 부대의 **롤은 유지** (전투 중 대량 롤 변신 금지 — 1:1:1 가독성 철칙).
- 대신 패시브 버프 소멸 + 충전 중이던 액티브 스킬 소멸(게이지 포함) → 별도 디버프 시스템 없이 "장군을 잃은 부대는 약해진다"가 자연 구현됨.
- 적 장군도 동일 규칙 → **"적 장군을 잡아라"가 모든 전투의 관람 서사**가 됨.

**타겟팅 연동**:
- TargetPriority에 Leader 케이스 추가 → 암살자의 우선순위를 원거리 → **장군 우선(참수)**으로 조정 검토. 암살자의 존재 이유가 완성됨.

**구현 노트**: 기존 GimmickTrigger/Effect 시스템 재사용, 효과 스코프에 "부대 단위" 케이스 추가. SquadDefinition에 리더 필드 확장. 병사 쪽(RoleData)의 트리거 기믹 필드는 제거하되 시스템 자체는 장군 스킬용으로 존치 (v4). 신규 시스템 최소화.

## 7. 롤 설계 (병사 6종) — v4 개정

**설계 규칙**:
- 타겟팅 로직은 2단계까지만: ① 위치 필터 → ② 타입/상태 우선순위.
- **병사는 트리거 기믹 없음 (v4 확정)** — 병사 롤의 개성은 이동 패턴 + 타겟팅(위치 필터/우선순위) + 스탯 프로필로만 구성. 마나 게이지 금지는 유지.
- 가독성 철칙 1:1:1 — 롤 1 : 실루엣 1 : 이펙트 색 1.

| 롤 | 역할 | 이동/타겟팅 (2단계) |
|---|---|---|
| 전사 | 벽/전선 유지 | 최근접 / 우선순위 없음 |
| 궁수 | 후열 화력 | 사거리 내 최근접 / 우선순위 없음 |
| 암살자 | 참수/후열 테러 | 가장 먼 열로 은신 돌진(N초) / **장군 우선** (검토) 또는 원거리 우선 |
| 사냥꾼 | 콤보 처형 | 사거리 내 / 중독·표식 대상 우선 |
| 사제 | 유지력 | 아군 / 체력 비율 낮은 아군 우선 |
| 광전사 | 돌파 | 적 밀집 지점 돌진 / 우선순위 없음 (광역) |

**v4 삭제 내역**: 병사 트리거 기믹 전면 삭제 — 전사 방패 무적 / 궁수 화살비 / 암살자 은신 해제 첫 타 치명타 / 사냥꾼 상태이상 추가 데미지 / 사제 정화 / 광전사 광폭화. 이동 패턴(암살자 은신 돌진)과 타겟팅(사냥꾼 중독·표식 우선)은 기믹이 아니므로 유지. 삭제된 기믹의 판타지 일부는 장군 액티브 스킬로 이관 (화살비→일제 사격, 은신 치명타→그림자 습격, 표식 처형→사냥 선포, 피해 감소→방진 — §6).

## 8. 상태이상 (공용 어휘 5종 — 확정, 구현 완료)

**기절 / 중독 / 화상 / 빙결(둔화) / 표식**

- 세 층이 같은 어휘 사용 (v4 개정): ① 플레이어 스킬이 부여 (번개=기절, 독구름=중독) ② 장군 액티브가 부여 (사냥 선포=표식) ③ 타겟팅 우선순위가 참조 (사냥꾼=중독·표식 우선).
- 구현: 공용 StatusEffectSystem 1개 (완료). 화상 치유감소/빙결·표식 세부 수치는 미확정 (§11).
- 셋업-페이오프 (v4 개정): 플레이어 스킬(셋업) × 타겟팅·장군 스킬(페이오프) 콤보 — 예: 독구름 중독 → 사냥꾼 우선 타겟 집중 / 사냥 선포 표식 → 추가 데미지.

## 9. 플레이어 스킬 (4종 확정 — v4)

- 쿨다운 기반, 전장 범위 지정 시전. 터치 UX: 스킬 버튼 탭 → 전장 탭/드래그로 위치 지정.

| 스킬 | 효과 | 구현 상태 |
|---|---|---|
| 번개 | 광역 데미지 + 기절 | 완료 |
| 독구름 | 장판 중독 | 완료 |
| 힐 장판 | 범위 아군 지속 회복 | 미구현 |
| 전투 함성 | 범위 아군 공격력 증가 — **버프 대상 발광 표시 필수** | 미구현 |

- 역할: 상태이상 부여 = 콤보의 셋업 + 병력 보호/강화. 전투 중 입력은 스킬 시전이 전부.
- 구현 노트: 힐 장판·전투 함성은 기존 장판(독구름) 구조 재사용, 회복·공격력 버프는 StatusEffectSystem의 긍정 효과 케이스로 구현 (신규 시스템 금지).

## 10. 기술 아키텍처 방침 (구현으로 검증됨)

- **데이터 드리븐**: 롤 = RoleData(SO) 하나. 롤 추가 = 데이터 1개 (검증 완료: 암살자·사냥꾼 데이터로만 추가됨). 장군도 동일 원칙: GeneralData(스탯 + 패시브: 부대 지속 버프 enum·수치 + 액티브: 충전 조건 enum + 필요량 + 효과) 데이터 정의.
- **로직/뷰 분리**: Simulation은 noEngineReferences 순수 C# 어셈블리 (System.Numerics.Vector2, 고정 틱+시드). 헤드리스 대량 시뮬 → AI 자동 밸런싱 파이프라인 가동 가능. 장군 유/무 × 패시브 수치별 승률 매트릭스 튜닝에 활용.
- **성능**: 스트레스 테스트 완료 기준 유닛 수 상한 준수. 타겟 재탐색 0.3~0.5초 주기+스태거링, 공간 해시, 오브젝트 풀, 틱 루프 내 GC 할당 금지.
- **아트**: 로우폴리/복셀 통일. AI는 텍스처·컨셉·아이콘·사운드 담당. 장군은 병사 대비 크기·실루엣·전용 이펙트로 즉시 구분.

## 11. 미확정 사항

**진행 구조 (메타 루프) — 미정. 후보:**
- 로그라이크 런 / 스테이지 클리어형 / 웨이브 서바이벌 / 단판 스코어 어택
- **장군이 진행 구조의 그릇이 될 수 있음**: 병사는 소모품, 장군은 자산(수집/성장 대상) — 어느 후보와도 결합 가능. 프로토타입 검증 후 결정.

**기타:**
- [ ] 장군 로스터 규모 (프로토타입 3~4명, 최종 몇 명?) / 장군 획득·성장 방식 (진행 구조와 연동)
- [ ] 사제·광전사 장군의 액티브 스킬 (확정 4종 외 — §6)
- [ ] 장군 액티브 충전 필요량 N / 지속 시간 K 등 수치 (시뮬로 튜닝)
- [ ] 암살자 우선 타겟: 장군 vs 원거리 (시뮬로 비교 검증)
- [ ] 화상/빙결의 정확한 수치 효과
- [ ] 적 군대 생성 규칙 (수동 설계 vs 절차 생성 vs AI 생성)
- [ ] 경제 재화 존재 여부
- [ ] 세로/가로 화면 방향 (가로 가정 중 — 조기 확정 필요)

## 12. 스코프 상한 (1달 기준)

- 병사 롤 6~8종 / 장군 4~6명 / 플레이어 스킬 4종 (확정) / 상태이상 5종 / 맵 1종
- 전투 콘텐츠 분량은 진행 구조 확정 후 산정.
- 남는 시간은 전부 타격감(넉백·랙돌·카메라)에 투자.

## 13. AI 활용 전략 (기술 문서용 스토리)

1. 설계·프로토타이핑: Claude로 구조 설계 → Claude Code로 단계별 구현 (진행 중, 프롬프트 로그 축적)
2. 콘텐츠 대량 생성: 데이터 드리븐 롤/장군 정의를 LLM으로 대량 생성
3. **자동 밸런싱**: 헤드리스 시뮬(순수 dotnet, AI가 직접 실행 가능) → 승률 측정 → AI 스탯 튜닝 자율 루프
4. 아트/사운드: 생성 AI (출처/라이선스 전부 기록 — 제출 요건)
5. 프롬프트·활용 내역은 docs/ai_usage_log.md에 즉시 기록

## 14. 프로토타입 재미 검증 목표

1. **관람이 재밌는가?** — 두 군대가 부딪히는 60초가 개입 없이도 볼만한가
2. **개입이 재밌는가?** — 스킬 한 방이 전황을 눈에 보이게 바꾸는가 (셋업→페이오프 콤보 가독성 — 예: 독구름 중독 → 사냥꾼 집중 타겟)
3. **배치가 의미 있는가?** — 같은 병력으로 장군 배치만 바꿨을 때 승패가 뒤집히는가
4. **장군이 서사를 만드는가?** — (v3 추가) 희소한 장군의 배치가 고민을 만드는가 / 적 장군 참수 → 부대 약화가 관람에서 읽히는가 / 장군 액티브 스킬(충전식, 전투당 2~3회)이 반복 소음이 아니라 전투의 "사건"으로 느껴지는가
5. **성능이 되는가?** — 기준 기기에서 목표 유닛 수 × 안정 프레임

→ 남은 검증 범위: 장군 시스템(시뮬) + 배치 화면 + 전투 1판 루프. 진행 구조는 검증 결과를 보고 결정.
