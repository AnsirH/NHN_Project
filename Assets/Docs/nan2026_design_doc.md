# NAN 2026 게임잼 — 기획 정리 문서 (프로토타입 기준) v2

> 목적: 재미 검증용 프로토타입 개발의 단일 참조 문서.
> 원칙: 이 문서에 없는 기능은 프로토타입에 넣지 않는다.

---

## 1. 프로젝트 개요

- **대회**: NHN NAN 2026 게임잼 사전 과제
- **팀**: 프로그래머 2인
- **엔진**: Unity (3D)
- **제출 빌드 제약**: 웹(GitHub Pages) 또는 모바일(APK/테스트 링크). **PC exe 금지.**
  - **기본 타겟: APK (모바일)** — WebGL 대비 성능 여유 확보
  - 트레이드오프 인지: 심사자 접근성은 웹이 유리(링크 클릭 한 번). APK는 설치 안내를 게임 소개 PDF에 매우 명확하게 작성할 것. 여유가 되면 저사양 WebGL 빌드를 보조로 제공하는 옵션도 열어둠.
  - 성능 기준 기기: 중급형 안드로이드 실기 1대를 지정하고, 모든 성능 판단은 그 기기 실측으로 한다.
- **제출물 5종**: 빌드+소스(GitHub, 커밋 기록 유지) / 플레이 영상 30~60초(YouTube) / 게임 소개 PDF / AI 활용 기술 문서 PDF / 팀원 롤 기술서 PDF
- **잼 성격**: "AI를 활용한 개발 과정" 자체를 심사. 게임 내 AI 탑재는 필수 아님.

## 2. 게임 컨셉

**한 줄 피치**: 노멀 병사들에게 깃발로 역할을 부여해 군대를 만들고, 꽝 부딪히는 대규모 군대 전투를 관람하며 플레이어 스킬로 거드는 3D 전투 관람 게임.

**레퍼런스 (우선순위 순)**:
1. **Mini Warriors** — 게임의 최우선 감각 목표. 군대 vs 군대가 우르르 충돌하는 물량감과 관람의 재미
2. **마인크래프트 점토병사 모드** — 톤앤매너와 롤 부여 감성의 원형: 밋밋한 병사에게 역할을 쥐여주면 군대가 되는 느낌
3. TABS / Attack on Toys — 물리 타격감(랙돌, 넉백, 진영 붕괴)
4. Stick War: Legacy — 자동전투 + 플레이어 스킬 개입의 밸런스
5. Art of War: Legions — 모바일 저사양에서 물량감 내는 연출

**세 개의 기둥**:
1. 군대 vs 군대 물량 스펙터클 (보는 재미가 본체)
2. 플레이어 스킬 개입 (번개, 독구름, 힐 장판 등)
3. 롤 부여 (게임의 정체성 훅: "아무것도 아닌 병사에게 내가 역할을 준다")

## 3. 코어 루프 (프로토타입 확정 범위)

```
[전투 전]  깃발 배치로 롤/비율/진형 결정
   ↓
[전투]    자동전투 관람 + 플레이어 스킬 타이밍 개입 (마이크로 조작 없음)
   ↓
[전투 후] 결과 확인 → 다음 전투
```

- **전투 종료 조건**: 한쪽 전멸.
- 전투와 전투를 잇는 **진행 구조(메타 루프)는 미정** — §10 참고. 프로토타입은 전투 1판의 재미 검증에 집중하며, 어떤 진행 구조를 붙여도 동작하도록 전투를 독립 모듈로 만든다.

## 4. 카메라 (방향 확정)

- **위에서 사선으로 내려다보는 탑다운/쿼터뷰 계열** 시점.
- 이 시점의 함의:
  - 원거리 투사체(화살 등)는 **포물선 궤적**이 자연스럽고 가독성이 좋다 → 롤 기믹 설계에 반영 (§5 궁수)
  - 진형(전열/후열/측면)이 한눈에 읽혀야 하므로 롤별 실루엣·색 구분이 중요
- 여유 시 검토: 충돌 순간 카메라 쉐이크, 대규모 격돌/보스 킬 순간의 연출 컷 (프로토타입 범위 외)

## 5. 배치 시스템 (깃발)

- 관리 단위는 **개인이 아니라 구역(분대)**. 병사가 늘어도 조작량 불변.
- 아군 진영 = 구역 그리드 (3×3 또는 4×3, 미확정 — §10)
- **깃발 1개 = 구역 1칸 = 롤 1종**. 깃발을 꽂으면 해당 구역 병사들이 그 롤로 변신.
- 병력 분배: 프로토타입은 자동 분배 우선 (슬라이더는 추후 검토)
- 전투 전 자유 재배치(리스펙) 허용
- 상성 카운터는 배율이 아니라 **배치로 푼다** (예: 적 암살자 多 → 내 궁수 옆에 전사 깃발)

## 6. 롤 설계 (6종)

**설계 규칙**:
- 타겟팅 로직은 **2단계까지만**: ① 위치 필터 → ② 타입/상태 우선순위. 3단계 이상 금지.
- 기믹은 **롤당 정확히 1개**, 마나 게이지 금지, **조건 트리거** 방식만 사용.
- 가독성 철칙 **1:1:1:1** — 롤 1 : 실루엣 1 : 기믹 1 : 이펙트 색 1.

| 롤 | 역할 | 이동/타겟팅 (2단계) | 트리거 기믹 (1개) |
|---|---|---|---|
| 전사 | 벽/전선 유지 | 최근접 / 우선순위 없음 | 주변 아군 3명 사망 시 방패 무적 2초 |
| 궁수 | 후열 화력 | 사거리 내 최근접 / 우선순위 없음 | 4번째 공격마다 **화살비**: 조준 지점에 포물선 화살 여러 발 낙하, 소범위 광역 데미지 |
| 암살자 | 후열 테러 | 가장 먼 열로 은신 돌진(N초) / 원거리 유닛 우선 | 은신 해제 첫 타 치명타 |
| 사냥꾼 | 콤보 처형 | 사거리 내 / **중독·표식 대상 우선** | 상태이상 대상에게 추가 데미지 |
| 사제 | 유지력 | 아군 / 체력 비율 낮은 아군 우선 | 주기적으로 아군 1명 상태이상 정화 |
| 광전사 | 도박/돌파 | 적 밀집 지점 돌진 / 우선순위 없음 (광역) | 체력 50% 이하 시 **광폭화** (하단 정의) |

**광폭화 정의 (초안 수치, 시뮬레이션으로 튜닝)**:
- 발동: 체력 50% 이하 도달 시 1회, 전투 종료 또는 사망까지 지속
- 효과: 공격속도 +50%, 이동속도 +30%, 공격력 +25%, **받는 피해 +25%** (리스크-리워드)
- 연출: 붉은 발광 + 크기 10% 증가 + 발동 순간 포효 이펙트 — 난전에서도 "쟤 터졌다"가 보여야 함

**궁수 기믹 노트**: 기본 공격도 포물선 궤적(사선 탑뷰 카메라와 어울림). 관통 화살은 포물선과 논리적으로 충돌하여 폐기. 화살비는 포물선의 시각적 장점을 그대로 증폭하는 기믹.

## 7. 상태이상 (공용 어휘 5종 — 확정)

**기절 / 중독 / 화상 / 빙결(둔화) / 표식**

- 시스템 전체가 공유하는 언어. 세 층이 같은 어휘 사용:
  1. 플레이어 스킬이 부여 (번개=기절, 독구름=중독 …)
  2. 유닛 기믹이 부여 (독칼 암살자=중독 …)
  3. 타겟팅 우선순위가 참조 (사냥꾼=표식/중독 우선 …)
- 효과 초안: 기절(행동 정지), 중독(도트 데미지), 화상(도트+치유 감소 등, 세부 미확정), 빙결(이동/공속 감소), 표식(받는 데미지 증가 + 특정 롤 우선 타겟)
- 구현: 공용 StatusEffect 컴포넌트 1개.
- 셋업-페이오프 원칙: 플레이어 스킬(셋업) × 롤 기믹(페이오프) 콤보.

## 8. 플레이어 스킬

- 3~4종, 쿨다운 기반 (마나 없음), 전장에 범위 지정 시전.
- 초안: 번개(광역 기절+데미지) / 독구름(장판 중독) / 힐 장판(범위 회복) / (+1 후보: 빙결 장판 또는 표식 부여)
- 역할: 단독 딜링이 아니라 **상태이상 부여 = 롤 콤보의 셋업** + 병력 보호.
- 전투 중 플레이어 입력은 스킬 시전이 전부. 마이크로 조작 금지.
- 모바일 타겟이므로 시전 UX는 터치 기준으로 설계 (스킬 버튼 탭 → 전장 탭/드래그로 위치 지정).

## 9. 기술 아키텍처 방침

- **데이터 드리븐 필수**: 롤 = ScriptableObject/JSON 하나로 정의.
  - `{ 스탯, 위치필터(enum), 우선순위(list), 이동패턴(enum), 트리거기믹(조건+효과), 이펙트색 }`
  - 롤 추가 = 데이터 한 줄. AI 대량 생성 파이프라인의 전제 조건.
  - 전투는 진행 구조(§10)와 독립된 모듈로: `전투 입력(양측 군대 정의) → 전투 → 결과 출력`. 어떤 메타 루프가 붙어도 재사용 가능해야 함.
- **성능 (모바일 APK 기준)**:
  - 1주차 최우선 과제: 더미 유닛 스트레스 테스트 빌드 → 기준 기기에서 "우리 스타일 기준 몇 마리까지 60fps(최소 30fps)"를 실측하고 그 숫자에 게임을 맞춘다.
  - 타겟 재탐색: 매 프레임 금지. 0.3~0.5초 주기 + 유닛별 시차(스태거링).
  - 유닛별 월드 UI(체력바) 최소화, 드로우콜/배칭 관리, 발열에 의한 스로틀링 고려(장시간 플레이 시 프레임 저하).
  - 물량감은 유닛 수가 아니라 연출로: 넉백, 랙돌, 진영 붕괴, 카메라 쉐이크, 먼지 이펙트.
  - 대량(수백)이 정말 필요하면 GPU instancing + VAT/ECS 검토 — 단, 2인 잼 스코프에서 비권장.
- **아트**: 로우폴리/복셀 등 단순 스타일 통일 (점토병사 감성과도 부합). AI는 텍스처·컨셉·아이콘·사운드 담당. 3D 메시 AI 생성은 스타일 일관성/리깅 리스크 있음. (바르코의 3D 지원 여부 + 타사 잼 사용 가능 여부 확인 필요)

## 10. 미확정 사항

**진행 구조 (메타 루프) — 전투 바깥을 어떻게 감쌀지 미정. 후보:**
- 로그라이크 런 (전투 후 보상 픽, 생존자 유지, 8~10전투 + 보스) — 이전 논의에서 유력했던 안이나 **채택 여부 미정**
- 스테이지 클리어형 (레벨 선택 + 별점)
- 웨이브 서바이벌 (끊김 없이 밀려오는 적, 사이사이 보강)
- 단판 스코어 어택 (심사용으로 가장 가벼움)
→ 프로토타입 재미 검증 결과를 보고 결정. 성장/보상/죽음 처리 규칙은 진행 구조가 정해진 뒤 함께 설계.

**기타:**
- [ ] 그리드 크기: 3×3(단순) vs 4×3(측면 플레이 여지)
- [ ] 화상/빙결의 정확한 수치 효과
- [ ] 4번째 플레이어 스킬 채택 여부
- [ ] 적 군대 생성 규칙 (수동 설계 vs 절차 생성 vs AI 생성)
- [ ] 경제 재화 존재 여부
- [ ] 세로/가로 화면 방향 (모바일 타겟이므로 조기 결정 필요 — 전장 가독성은 가로 유리)

## 11. 스코프 상한 (1달 기준)

- 롤 6~8종 / 플레이어 스킬 3~4종 / 상태이상 5종 / 맵 1종
- 전투 콘텐츠 분량(스테이지 수 등)은 진행 구조 확정 후 산정
- 남는 시간은 전부 타격감(넉백·랙돌·카메라)에 투자. 이 장르는 부딪히는 순간이 전부.

## 12. AI 활용 전략 (기술 문서용 스토리)

차별화 포인트: "코드/이미지 생성" 수준을 넘어 **AI를 개발 프로세스에 구조적으로 통합**.

1. 설계·프로토타이핑: Claude로 구조 설계 → Claude Code로 구현 (본 문서가 그 산출물)
2. 콘텐츠 대량 생성: 데이터 드리븐 롤 정의를 LLM으로 대량 생성 (변형 롤, 적 조합)
3. **자동 밸런싱**: 헤드리스 시뮬레이션으로 조합 간 승률 측정 → AI로 스탯 튜닝 반복
4. 아트/사운드: 생성 AI로 텍스처·아이콘·컨셉·SFX (출처/라이선스 전부 기록 — 제출 요건)
5. 프롬프트·활용 내역은 개발 중 즉시 기록 (나중에 복원 불가)

## 13. 프로토타입 재미 검증 목표

프로토타입이 답해야 할 질문 (이것만 만들고 멈춰서 평가):

1. **관람이 재밌는가?** — 두 군대가 부딪히는 60초가 아무 개입 없이도 볼만한가 (타격감/가독성)
2. **개입이 재밌는가?** — 스킬 한 방이 전황을 눈에 보이게 바꾸는가 (기절→처형 콤보가 읽히는가)
3. **배치가 의미 있는가?** — 같은 병력으로 깃발 배치만 바꿨을 때 승패가 뒤집히는가
4. **성능이 되는가?** — 기준 안드로이드 기기에서 목표 유닛 수 × 안정 프레임

→ 검증 범위: 롤 3종(전사/궁수/암살자) + 상태이상 2종(기절/중독) + 스킬 2종(번개/독구름) + 전투 1판. 진행 구조는 검증 결과를 보고 결정.
