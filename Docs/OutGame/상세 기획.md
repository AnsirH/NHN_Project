# 상세 기획서 — 아웃게임

> 2026-07-14 작성. [[초기 기획]]을 고도화한 문서.
> 근거 자료: [[사전 조사]], [[레퍼런스 적용 방안]]
> 설계 결정은 팀 논의(2026-07-14)로 확정. 미결 항목은 §9 참조.

## 1. 개요

- **게임**: Mini Warriors 모티브의 다대다 전투 게임 + 로그라이크(랜덤 맵 + 증강) 요소
- **이 문서의 범위**: 아웃게임 전체 — 메인 메뉴, 맵 선택, 방 그래프, 방 이벤트, 군대/아이템, 군대 배치 UI, 인게임 데이터 인터페이스
- **범위 외**: 인게임 전투 (별도 개발자 담당 — 우리는 §7 인터페이스로 데이터만 전달)
- **핵심 설계 원칙**
  1. **데이터 주도**: 층 수, 노드 수, 확률, 아이템 효과 등 밸런스 값은 전부 ScriptableObject/설정 데이터로 분리해 코드 수정 없이 조정 가능해야 한다 (확정 요구사항)
  2. **재사용 가능한 UI**: 방 선택·군대 배치 UI는 인게임 개발자가 바로 쓸 수 있는 프리팹 + 컴포넌트로 제작
  3. **검증된 것 재사용**: 방 그래프는 silverua STS 맵(MIT) 이식, UX는 Mini Warriors/STS 참조

## 2. 용어

| 용어 | 정의 |
|------|------|
| **런(Run)** | 맵 선택 → 보스 처치(또는 패배)까지의 1회 플레이. 패배 시 런 종료 (로그라이크) |
| **맵(Map)** | 하나의 스테이지. 방 노드 그래프로 구성. 1차 구현은 맵 1개 |
| **방(Room)** | 그래프의 노드. 타입: 일반전투/보스/이벤트/휴식 |
| **군대(Army)** | 배치·전투의 기본 단위(부대). 병사 여러 명의 묶음 |
| **기본 군대** | 아이템 미부여 상태의 군대. 병과 없음 |
| **병과** | 아이템 부여로 결정되는 군대의 역할 (활→궁수, 안장→기마) |
| **장군** | 군대를 이끄는 유닛. 군대마다 1명 상시 존재 (기본 군대 포함). 대열 선두, 일반 병사보다 높은 스탯. 병과가 생기면 전용 스킬을 자동 사용 (플레이어 조작 아님). 기본 군대 상태에서는 스킬 없음 |
| **귀속** | 아이템을 군대에 부여하면 회수/이전 불가 |

## 3. 씬 구조와 게임 흐름

### 3.1 씬 구성 (3개)

| 씬 | 이름(파일) | 역할 |
|----|-----------|------|
| 메인 메뉴 | `MainMenu.unity` | 타이틀, 게임 시작, (이어하기), 종료 |
| 맵 선택 | `MapSelect.unity` | 맵 목록 표시 (1차: 맵 1개), 선택 시 런 생성 후 인게임 씬 로드 |
| 인게임 | `InGame.unity` | 방 그래프 UI → 방 선택 → (전투 방이면) 배치 UI → 전투 → 결과 → 그래프 복귀 루프 |

### 3.2 런 흐름

```
메인 메뉴 ─ 게임 시작 → 맵 선택 ─ 맵 확정(RunState 생성, 기본 군대 지급) → 인게임 씬
                                                                        │
    ┌───────────────────────────────────────────────────────────────────┘
    ▼
  방 그래프 UI (현재 위치에서 연결된 다음 층 노드만 선택 가능)
    │
    ├─ 이벤트 방 → 이벤트 패널(선택지) → 보상 적용 → 그래프 복귀
    ├─ 휴식 방   → 휴식 패널(증원 선택) → 효과 적용 → 그래프 복귀
    └─ 전투/보스 방 → 군대 배치 UI → 배치 확정(BattleSetupData 생성)
                        → 인게임 전투 → BattleResultData 수신
                            ├─ 승리: 보상 → 그래프 복귀 (보스 승리 시 런 클리어)
                            └─ 패배: 런 종료 → 결과 화면 → 메인 메뉴
```

## 5. 시스템 상세

### 5.1 메인 메뉴

- 구성: 타이틀 로고, [게임 시작], [이어하기](진행 중 런 있을 때만 활성), [종료]
- 게임 시작 → 맵 선택 씬. 이어하기 → 저장된 RunState 로드 후 인게임 씬
- 1차 구현에서는 설정/크레딧 제외

### 5.2 맵 선택

- **월드맵 스타일** (UI 기획 이미지 기준): 배경 일러스트 위에 맵 진입점 배치. 1차는 맵 1개
- 맵 진입점: 맵 이름, 대표 이미지, 난이도 표기
- 맵 선택 → RunState 생성(맵 그래프 생성 + 기본 군대 지급) → 인게임 씬 로드
- 맵이 1개여도 씬과 UI는 복수 맵 전제로 구현 (MapDefinition 목록 기반)

### 5.3 방 그래프 (인게임 씬 내 UI)

**생성 규칙** — STS 원작 알고리즘, silverua 구현 이식 (상세: [[레퍼런스 적용 방안]] §1):

1. `층 수 × 층당 최대 노드 수` 격자 생성 (기본 10×5, MapConfig로 조정)
2. 1층에서 상향 경로 N개 생성 (기본 5개, config). 시작 노드 최소 2개, 경로 교차 금지
3. 경로에 포함되지 않은 노드 제거
4. 방 타입 배정:

| 규칙 | 값 (초안 — 전부 MapConfig 데이터) |
|------|----------------------------------|
| 고정 층 | 1층 = 일반전투, 최상층(10층) = 보스, 보스 직전 층(9층) = 휴식 |
| 나머지 층 확률 | 일반전투 55% / 이벤트 30% / 휴식 15% |
| 제약 | 휴식 연속 금지 · 한 노드에서 갈라지는 분기의 목적지 방 타입은 서로 달라야 함 · 2층은 항상 일반전투 또는 이벤트 |

> 확률 초안 근거: STS 원작(전투53/미지22/휴식12/엘리트8/상점5)에서 미제외 타입(미지·엘리트·상점 35%)을 전투·이벤트에 재분배. 이벤트가 군대/아이템 수급의 유일한 수단이므로 이벤트 비중을 높게 설정.

**진행 규칙**:
- 현재 노드에서 선으로 연결된 다음 층 노드만 선택 가능 (그 외는 비활성 표시)
- 방문한 노드·경로는 시각적으로 구분
- 맵 상태는 런 저장 데이터에 포함 (이어하기 지원)
- 우측 상단에 **방 종류 범례 패널** 표시 (아이콘 + 이름 — UI 기획 이미지 반영)

### 5.4 이벤트 방 (선택지형)

- 진입 시 이벤트 패널: 일러스트 + 상황 텍스트 + 선택지 2~3개
- 선택 결과: 군대 획득 / 아이템 획득 / 복합(예: 군대를 얻지만 다음 전투 디버프 — 2차) 등
- 데이터: `EventDefinition` (ScriptableObject)
  - 일러스트, 본문 텍스트
  - 선택지 목록: [선택지 텍스트, 결과 목록(군대 지급/아이템 지급/없음), 결과 연출 텍스트]
- 이벤트 풀에서 랜덤 추첨 (동일 런 내 중복 방지)
- 1차 콘텐츠 목표: 이벤트 6~8종 (군대 획득형 3, 아이템 획득형 3, 선택 갈등형 1~2)

### 5.5 군대 시스템

- **기본 군대**: 병과 없음. 기본 스탯(병사 수, 공격력, 체력 등)은 `ArmyDefinition`(SO)에 정의
- **병과**: 부여된 아이템 1개로 결정 — `기본 군대 + 활 = 궁수 군대`, `+ 안장 = 기마 군대`
- **장군** (2026-07-16 확정):
  - 군대마다 1명 상시 존재 — 기본 군대에도 있음. 대열 선두에서 군대를 이끎
  - 일반 병사보다 높은 스탯 (배율/보정값은 `ArmyDefinition`에 정의)
  - **전용 스킬**: 병과가 생기면(아이템 부여 시) 해당 병과의 장군 스킬을 획득. 장군 유닛이 자동 사용 (플레이어 조작 없음). 기본 군대 상태에서는 스킬 없음 → 스킬 정의는 `ItemDefinition`에 귀속 (아이템=병과=스킬 세트)
  - 경험치/성장: 군대 정보 팝업에 경험치 표시 영역 존재 — 성장 규칙은 미결(§9)
- **획득**: 런 시작 시 기본 군대 2~3개(config) + 이벤트 방 보상. 보유 상한 없음
- **병력 손실 없음**: 전투에서 전멸해도 전투 종료 후 완전 회복. 부대와 귀속 아이템은 런 내 영구 자산
  - 의도: 다대다 소모전(수많은 병사가 부딪혀 겨우 이기는 그림)을 인게임에서 연출하되, 아웃게임 관리 부담은 제거
  - 이 결정에 따라 **휴식 방은 회복이 아닌 "증원" 방으로 재정의** (아래)

**휴식 방 (재정의 — 제안)**:
- 효과: 보유 군대 중 1개 선택 → 병사 수 영구 +20% (config)
- 대안(2차 검토): 아이템 1개 획득과 택일 제시
- ※ 병력 손실 모델이 바뀌면(§9 미결 참조) 회복 기능으로 환원 가능하도록 효과를 데이터로 정의

### 5.6 아이템 시스템

- **슬롯**: 부대당 1개. 이미 아이템이 있는 부대에는 부여 불가 (교체 없음 — 귀속)
- **데이터**: `ItemDefinition` (ScriptableObject)
  - 아이콘, 이름, 설명
  - 부여 시 병과 (`ArmyClass` enum: Archer, Cavalry, …)
  - 스탯 보정값 (사거리, 이동속도, 공격력 등 — 인게임 협의 필드)
  - 예약 필드(1차 미사용): 카테고리, 선행 아이템 (점토병사식 확장 대비)
- **1차 아이템**: 활(→궁수), 안장(→기마) 2종. 이후 점토병사 카테고리표([[사전 조사]] §2) 참고해 확장
- **장군 스킬 컨셉 초안** (§4-23 — 효과 수치는 인게임 조율):

| 아이템 | 병과 | 장군 스킬 (초안) | 컨셉 |
|--------|------|-----------------|------|
| 활 | 궁수 | 일제 사격 (Volley) | 범위 내 다수 적에게 원거리 일제 공격 |
| 안장 | 기마 | 돌격 (Charge) | 전방 돌진 + 충격 피해, 진형 붕괴 |
- **귀속 경고 팝업** (기획서 필수 요구):
  - 아이템을 부대에 드롭하는 순간 표시: "이 아이템은 부대에 귀속되며 되돌릴 수 없습니다"
  - [부여] / [취소] + **[다시 표시하지 않음] 체크박스**
  - 체크 시 PlayerPrefs에 영구 저장, 이후 팝업 생략하고 즉시 부여
  - 의도: 경고를 통한 자연스러운 메커니즘 학습 (기획서 명시)

**화면 와이어프레임**: `참고 이미지/아웃게임UI기획이미지.png` (2026-07-16 — 전체 플로우 + 배치 화면 + 팝업 2종 확정본)

참고 이미지에서 가져오는 구조:
- **좌측: 보유 군대 목록 패널** (세로 스크롤, 부대 초상+이름+레벨/병과 표시)
- **우측: 배치 슬롯 영역** — 아군 진영. 슬롯은 격자형 고정 배열
- **드래그 앤 드롭**: 목록의 부대를 잡아 슬롯에 놓으면 배치, 슬롯 간 이동/스왑 가능, 목록으로 되돌리면 배치 해제
- 상단: 배치 수 카운터 (예: 6/9), 하단: [전투 시작] 버튼
- 전투 필드 기준 아군 진영=좌측, 적 진영=우측 (Mini Warriors와 동일)

**화면 레이아웃 (2026-07-16 UI 기획 이미지 확정)**:
- 좌 **플레이어 진영** / 우 **적 진영** — 양쪽 슬롯 그리드 대칭 표시
- 중앙 세로 축 (위→아래): **적 버프 표시**(1차는 "없음" 고정 표시 — §4-21) → **[전투 시작]** → **[아이템]** 버튼 → **[프리셋]** 버튼(1차 비활성)
- 양 진영 하단: **전투력** 수치 — 초안 공식(§4-22): `Σ(병사 수 × 병과 계수) + 장군 보정`. 병과 계수(초안: 기본 1.0 / 궁수 1.2 / 기마 1.5)와 장군 보정값은 config

우리 게임 추가 요소:
- **아이템 부여는 인벤토리 팝업 방식** (§4-19 개정): [아이템] 버튼 → 인벤토리 팝업(제목 + 기능 버튼 + 아이템 스크롤뷰) → 아이템을 부대(목록 또는 슬롯 위)로 드래그 앤 드롭 부여 (§5.6 귀속 팝업 연동)
- **군대 정보 팝업**: 배치 화면에서 군대 클릭 시 — 좌측 장군 프리뷰/경험치/장군 스탯, 우측 군대 정보/군대 스탯, 상단 재화 표시, 닫기 버튼
- 부대에 부여된 아이템/병과는 부대 아이콘에 뱃지로 표시
- 적 정보 미리보기: 적 진영 슬롯 + 적 버프 표시 (전술 판단 근거)

**배치 슬롯 사양 (초안 — config)**:
- 슬롯 배열: 3행 × 3열 = 9슬롯 (BattleFieldConfig로 조정 가능)
- 각 슬롯은 ID + 정규화 좌표(진영 내 0~1)를 가짐 → 인게임이 실제 월드 좌표로 변환
- 빈 슬롯 허용 (최소 1개 부대 배치해야 전투 시작 가능)

**프리팹화 요구사항** (기획서: 인게임 개발자가 바로 사용 가능해야 함):
- `ArmyDeploymentPanel` 프리팹: 외부에서 `Open(RunState, RoomInfo)` 호출 → 완료 시 `OnConfirmed(BattleSetupData)` 이벤트 발행. 씬 의존성 없음
- `RoomMapPanel` 프리팹(방 그래프)도 동일 패턴: `Open(RunState)` → `OnRoomSelected(RoomInfo)`

### 5.8 방 이벤트 연출

- 공통 연출: 방 노드 선택 → 카메라/패널 전환(DOTween) → 방 타입별 패널 오픈
- 이벤트/휴식: 패널 페이드 인, 보상 획득 시 아이콘 플라이 연출(획득물이 인벤토리 방향으로 이동)
- 전투: 배치 확정 → 전장 전환 연출은 인게임 담당 (전환 신호만 우리가 발행)
- 1차 수준: 정적 패널 + DOTween 트윈(페이드/스케일/플라이). 타임라인 컷신은 범위 외

## 6. 데이터 구조

```
[에셋 데이터 - ScriptableObject]                [런타임 데이터 - 직렬화 가능 POCO]
MapDefinition     (맵 목록용: 이름, 이미지)      RunState        (런 전체 상태 — 저장 대상)
MapConfig         (층수, 노드수, 경로수,          ├ MapState     (생성된 그래프 + 방문 기록)
                   확률표, 제약 규칙)             ├ List<ArmyInstance>  (보유 군대)
ArmyDefinition    (기본 군대 스탯 + 장군 스탯/외형) │   └ armyDefId, 증원 보정, 부여된 itemId
ItemDefinition    (병과, 스탯 보정, 장군 스킬,      └ List<string> (보유 아이템 itemId)
                   예약 필드)                      ※ 재화 잔액도 RunState에 포함 (§4-18)
EventDefinition   (이벤트 텍스트/선택지/보상)
BattleFieldConfig (슬롯 배열, 좌표)
RoomEncounterTable(방 타입별 적 구성 — 인게임 협의)
```

- 순수 로직·데이터 클래스는 `OutGame.Logic` 어셈블리 (MonoBehaviour 금지) → EditMode 테스트 대상
- RunState 저장: JSON 직렬화 → `Application.persistentDataPath` (이어하기 지원)

## 7. 인게임 인터페이스 (아웃게임 확정안)

인게임 개발자에게 전달하는 계약. **이 섹션이 곧 인터페이스 명세**이며 변경 시 양측 합의 필요.

### 7.1 아웃게임 → 인게임: `BattleSetupData`

```csharp
// OutGame.Logic — 직렬화 가능, Unity 타입 미사용
public class BattleSetupData
{
    public string roomId;              // 방 노드 ID
    public RoomType roomType;          // NormalBattle | Boss
    public string encounterId;         // RoomEncounterTable 키 (적 구성)
    public List<DeployedArmy> armies;  // 배치 결과
}

public class DeployedArmy
{
    public string armyInstanceId;
    public string armyDefId;           // ArmyDefinition 키
    public ArmyClass armyClass;        // None | Archer | Cavalry | ...
    public string equippedItemId;      // 없으면 null
    public int soldierCount;           // 증원 보정 반영된 최종 병사 수
    public int slotId;                 // 배치 슬롯 ID
    public float slotX, slotY;         // 진영 내 정규화 좌표 (0~1), 아군 진영=좌측
}
```

### 7.2 인게임 → 아웃게임: `BattleResultData`

```csharp
public class BattleResultData
{
    public string roomId;
    public bool victory;               // false → 아웃게임이 런 종료 처리
    // 예약(1차 미사용): 부대별 생존 수 — 병력 손실 모델 변경 대비
    public List<ArmySurvival> survivals;
}
```

### 7.3 호출 규약

- 아웃게임이 `BattleSetupData` 생성 → 정적 브릿지(`BattleBridge.StartBattle(setup, onResult)`)로 인게임 호출
- 인게임은 전투 종료 시 `onResult(BattleResultData)` 콜백 — 씬 전환 방식(동일 씬 내 전환 vs 별도 씬)은 인게임 개발자 선택에 맡기되 콜백 계약은 유지
- 병력 손실 없음 모델이므로 1차에서 아웃게임은 `victory`만 소비. `survivals`는 모델 변경 대비 예약

## 8. 구현 우선순위

| 단계 | 내용 | 산출물 |
|------|------|--------|
| M1 | 데이터 기반 + 방 그래프 로직 (silverua 이식, OutGame.Logic, EditMode 테스트) | 그래프 생성·직렬화 로직 |
| M2 | 인게임 씬: 방 그래프 UI (RoomMapPanel 프리팹 + 방 종류 범례) + 방 진행 루프 | 노드 선택 → 더미 방 → 복귀 동작 |
| M3 | 군대(장군 포함)/아이템 데이터 + 배치 UI (ArmyDeploymentPanel, 드래그 앤 드롭, 귀속 팝업, 군대 정보 팝업, 인벤토리 팝업, 전투력 표시) | BattleSetupData 생성까지 |
| M4 | 이벤트/휴식 방 (EventDefinition, 패널, 보상 지급 — 재화 포함) | 이벤트 6종 |
| M5 | 메인 메뉴 + 맵 선택 씬 + 런 저장/이어하기 | 전체 루프 완성 |
| M6 | 연출(DOTween), 더미 전투 브릿지로 통합 테스트, 인게임 연결 | 인수인계 가능 상태 |

> M1~M3이 인게임 개발자 의존성이 가장 큰 구간 — §7 인터페이스를 M1 시점에 공유한다.
