## 1. 개요

- **게임**: Mini Warriors 모티브의 다대다 전투 게임 + 로그라이크(랜덤 맵 + 증강) 요소
- **이 문서의 범위**: 아웃게임 전체 — 메인 메뉴, 맵 선택, 방 그래프, 방 이벤트, 군대/아이템, 군대 배치 UI, 인게임 데이터 인터페이스
- **범위 외**: 인게임 전투 (별도 개발자 담당 — 우리는 §7 인터페이스로 데이터만 전달)
- **핵심 설계 원칙**
  1. **데이터 주도**: 층 수, 노드 수, 확률, 아이템 효과 등 밸런스 값은 전부 ScriptableObject/설정 데이터로 분리해 코드 수정 없이 조정 가능해야 한다 (확정 요구사항)
  2. **재사용 가능한 UI**: 방 선택·군대 배치 UI는 인게임 개발자가 바로 쓸 수 있는 프리팹 + 컴포넌트로 제작
  3. **검증된 것 재사용**: 방 그래프는 silverua STS 맵(MIT) 이식, UX는 Mini Warriors/STS 참조

## 2. 용어

| 용어 | 정의 |
|------|------|
| **런(Run)** | 맵 선택 → 보스 처치(또는 패배)까지의 1회 플레이. 패배 시 런 종료 (로그라이크) |
| **맵(Map)** | 하나의 스테이지. 방 노드 그래프로 구성. 1차 구현은 맵 1개 |
| **방(Room)** | 그래프의 노드. 타입: 일반전투/보스/이벤트/증원 |
| **군대(Army)** | 배치·전투의 기본 단위(부대). 병사 여러 명의 묶음 |
| **기본 군대** | 아이템 미부여 상태의 군대. 병과 없음 |
| **병과** | 아이템 부여로 결정되는 군대의 역할 — 활→궁수, 검+방패→전사, 도끼→사냥꾼, 단검→암살자 (2026-07-26 개정, §4-30) |
| **장군** | 군대를 이끄는 유닛. 군대마다 1명 상시 존재 (기본 군대 포함). 대열 선두, 일반 병사보다 높은 스탯. 병과가 생기면 전용 스킬을 자동 사용 (플레이어 조작 아님). 기본 군대 상태에서는 스킬 없음 |
| **귀속** | 아이템을 군대에 부여하면 회수/이전 불가 |
| **군대 업그레이드** (2026-07-19 신규) | 재화를 소비해 군대 1개의 장군·유닛 스탯을 강화. 군대별로 0~+5 단계, 군대 정보 UI에서 실행. 장군 경험치 시스템을 대체 (§5.5) |
| **증강** (2026-07-19 신규) | 증강 방에서 3개 중 1개를 선택해 얻는 런 전체 영구 효과. 아이템(병과)별 증강과 공통 유닛 스탯 증강으로 구성 (§5.6) |
| **난이도 커브 카운터** (2026-07-26 신규) | `RunState.powerRoomsVisited` — 증원·증강·이벤트 방을 지난 횟수. 전투 승리 드롭은 확률적이라 제외. 적 생성이 이 값을 기준으로 반응한다 (§4-29) |
| **티어(Tier)** (2026-07-26 신규) | 난이도 커브 카운터 구간 하나 — "적 수 + 병과별 등장 가중치 + 보스 구성"을 함께 묶어 계단식으로 관리 (`DifficultyTier`, §4-29) |

## 3. 씬 구조와 게임 흐름

### 3.1 씬 구성 (4개, 2026-07-26 캐릭터 선택 추가)

| 씬 | 이름(파일) | 역할 |
|----|-----------|------|
| 메인 메뉴 | `MainMenu.unity` | 타이틀, 게임 시작, (이어하기), 종료 |
| 맵 선택 | `MapSelect.unity` | 맵 목록 표시 (1차: 맵 1개), 선택 시 런 생성 후 캐릭터 선택 씬 로드 |
| 캐릭터 선택 | `CharacterSelect.unity` | 플레이어 캐릭터 4종 중 1개 선택 (§5.2.5), 확정 시 인게임 씬 로드 |
| 인게임 | `InGame.unity` | 방 그래프 UI → 방 선택 → (전투 방이면) 배치 UI → 전투 → 결과 → 그래프 복귀 루프 |

이어하기(저장된 RunState 로드)는 이미 캐릭터가 선택된 상태이므로 캐릭터 선택 씬을 거치지 않고 바로
인게임 씬으로 간다 — 캐릭터 선택은 "새 런을 시작할 때"만 나오는 단계.

### 3.2 런 흐름

```
메인 메뉴 ─ 게임 시작 → 맵 선택 ─ 맵 확정(RunState 생성, 기본 군대 지급) → 캐릭터 선택 씬
                                                                        │
    ┌───────────────────────────────────────────────────────────────────┘
    ▼
  캐릭터 선택 (§5.2.5, 4종 중 1개) ─ 확정 시 RunState.selectedCharacterId 채움 → 인게임 씬
                                                                        │
    ┌───────────────────────────────────────────────────────────────────┘
    ▼
  방 그래프 UI (현재 위치에서 연결된 다음 층 노드만 선택 가능)
    │
    ├─ 이벤트 방 → 이벤트 패널(선택지) → 보상 적용 → 그래프 복귀
    ├─ 증원 방   → 증원 패널(대상 선택) → 효과 적용 → 그래프 복귀
    └─ 전투/보스 방 → 군대 배치 UI → 배치 확정(BattleSetupData 생성)
                        → 인게임 전투 → BattleResultData 수신
                            ├─ 승리: 보상 → 그래프 복귀 (보스 승리 시 런 클리어)
                            └─ 패배: 런 종료 → 결과 화면 → 메인 메뉴
```

## 5. 시스템 상세

  §5.2.5 — 이전엔 여기서 바로 인게임 씬으로 갔으나 캐릭터 선택 단계가 사이에 추가됨)
- 맵이 1개여도 씬과 UI는 복수 맵 전제로 구현 (MapDefinition 목록 기반)

### 5.2.5 캐릭터 선택 (2026-07-26 신규)

맵 확정 직후, 인게임 씬 진입 전에 플레이어가 조종할 주인공 캐릭터를 고르는 화면. Slay the Spire류
레이아웃 참고 — 좌측에 캐릭터 이름/설명 패널과 스킬 설명 패널, 우측에 대형 초상화, 하단에 캐릭터
초상화 아이콘을 가로로 나열하고 좌우 화살표로 넘길 수 있다. 선택된 아이콘만 하이라이트되고 나머지는
흑백(회색 틴트)으로 표시된다. 화살표/아이콘 클릭 모두 같은 방식으로 미리보기를 전환하며, 별도
확인 버튼("이 캐릭터로 시작")을 눌러야 확정된다.

**플레이어 캐릭터는 스킬을 정확히 하나만 가진다** — 어떤 캐릭터를 고르느냐가 곧 인게임에서 쓸
스킬을 결정한다. 스킬의 세부 효과(수치, 발동 조건 등)는 아웃게임이 정의하지 않는다 — §4-23(장군
스킬)·§4-27(`generalSkillUpgradeCount`)과 동일한 원칙으로, "어떤 스킬을 선택했는지"만 인게임에
전달하고 실제 구현은 인게임 스킬 시스템 책임이다.

```csharp
// OutGame.Logic.Characters — 순수 로직, PlayerCharacterDefinition(SO)의 ToData() 결과
public class PlayerCharacterData
{
    public string id;
    public string displayName;
    public string description;      // 선택 화면 표시용
    public string skillId;          // §7 계약에 실리는 값 — 인게임 스킬 시스템의 키
    public string skillName;        // 선택 화면 표시용 (placeholder)
    public string skillDescription; // 선택 화면 표시용 (placeholder, 실제 효과는 인게임 책임)
}
```

1차 구현은 캐릭터 4종 전부 **플레이스홀더**(이름/설명/스킬명 임시 텍스트, 초상화 미정) —
`SceneSetupM7Data.Run()`으로 생성(`char_1`~`char_4`). 실제 캐릭터 콘텐츠(이름/설명/스킬/초상화)는
추후 기획·아트 자산이 확정되면 교체한다. 확정된 선택은 `RunState.selectedCharacterId`에 저장되고,
전투마다 `BattleSetupData.playerCharacterId`/`playerCharacterSkillId`로 인게임에 전달된다(§7.1).

### 5.3 방 그래프 (인게임 씬 내 UI)

**생성 규칙** — STS 원작 알고리즘, silverua 구현 이식 (상세: [[레퍼런스 적용 방안]] §1):

1. `층 수 × 층당 최대 노드 수` 격자 생성 (기본 10×5, MapConfig로 조정)
2. 1층에서 상향 경로 N개 생성 (기본 5개, config). 시작 노드 최소 2개, 경로 교차 금지
3. 경로에 포함되지 않은 노드 제거
4. 방 타입 배정:

| 규칙 | 값 (초안 — 전부 MapConfig 데이터) |
|------|----------------------------------|
| 고정 층 | 1층 = 일반전투, 최상층(10층) = 보스, 보스 직전 층(9층) = 증원 |
| 나머지 층 확률 | 일반전투 40% / 이벤트 25% / 증원 15% / 증강 20% (2026-07-19 개정 — 증강 방 추가로 재분배) |
| 제약 | 증원 연속 금지 · 한 노드에서 갈라지는 분기의 목적지 방 타입은 서로 달라야 함 · 2층은 항상 일반전투 또는 이벤트 |

> 확률 초안 근거: STS 원작(전투53/미지22/휴식12/엘리트8/상점5)에서 미제외 타입(미지·엘리트·상점 35%)을 전투·이벤트·증강에 재분배. 이벤트가 군대/아이템 수급의 주요 수단이고, 증강은 전투 승리 드롭(§5.6)이 아이템 수급을 일부 대체하게 된 점을 고려해 비중을 나눔. 전부 config — 플레이 테스트로 조율. (STS의 "휴식" 표기는 원작 명칭 인용 — 우리 쪽 방 이름은 "증원"으로 개칭됨)

> 방 타입은 1차 **일반전투/보스/이벤트/증원/증강 5종**으로 확장 (§4-2 개정, 2026-07-19). 방 종류 범례 패널(§5.3 하단)에도 증강 아이콘 추가 필요. (2026-07-26: "휴식" 방을 "증원" 방으로 개칭 — 실제 효과가 회복이 아닌 병사 수 영구 증원이라 원래부터 이름이 안 맞았음)

**진행 규칙**:
- 현재 노드에서 선으로 연결된 다음 층 노드만 선택 가능 (그 외는 비활성 표시)
- 방문한 노드·경로는 시각적으로 구분
- 맵 상태는 런 저장 데이터에 포함 (이어하기 지원)
- 우측 상단에 **방 종류 범례 패널** 표시 (아이콘 + 이름 — UI 기획 이미지 반영)

### 5.4 이벤트 방 (선택지형)

- 진입 시 이벤트 패널: 일러스트 + 상황 텍스트 + 선택지 2~3개
- 선택 결과: 군대 획득 / 아이템 획득 / 복합(예: 군대를 얻지만 다음 전투 디버프 — 2차) 등
- 데이터: `EventDefinition` (ScriptableObject)
  - 일러스트, 본문 텍스트
  - 선택지 목록: [선택지 텍스트, 결과 목록(군대 지급/아이템 지급/없음), 결과 연출 텍스트]
- 이벤트 풀에서 랜덤 추첨 (동일 런 내 중복 방지)
- 1차 콘텐츠 목표: 이벤트 6~8종 (군대 획득형 3, 아이템 획득형 3, 선택 갈등형 1~2)

### 5.5 군대 시스템

- **기본 군대**: 병과 없음. 기본 스탯(병사 수, 공격력, 체력 등)은 `ArmyDefinition`(SO)에 정의
- **병과**: 부여된 아이템 1개로 결정 — `기본 군대 + 활 = 궁수 군대`, `+ 검+방패 = 전사 군대`, `+ 도끼 = 사냥꾼 군대`, `+ 단검 = 암살자 군대` (2026-07-26 개정, §4-30 — 4병과 확장)
- **장군** (2026-07-16 확정):
  - 군대마다 1명 상시 존재 — 기본 군대에도 있음. 대열 선두에서 군대를 이끎
  - 일반 병사보다 높은 스탯 (배율/보정값은 `ArmyDefinition`에 정의)
  - **전용 스킬**: 병과가 생기면(아이템 부여 시) 해당 병과의 장군 스킬을 획득. 장군 유닛이 자동 사용 (플레이어 조작 없음). 기본 군대 상태에서는 스킬 없음 → 스킬 정의는 `ItemDefinition`에 귀속 (아이템=병과=스킬 세트)
  - ~~경험치/성장~~ **제거** (2026-07-19, §4-24) — 아래 "군대 업그레이드"로 통합
- **획득**: 런 시작 시 기본 군대 2~3개(config) + 이벤트 방 보상. **보유 상한 = 배치 슬롯 수**(2026-07-18 개정, §4-7) — 상한 도달 시 이벤트 보상으로도 추가 획득 불가하며 실패를 안내
- **병력 손실 없음**: 전투에서 전멸해도 전투 종료 후 완전 회복. 부대와 귀속 아이템은 런 내 영구 자산
  - 의도: 다대다 소모전(수많은 병사가 부딪혀 겨우 이기는 그림)을 인게임에서 연출하되, 아웃게임 관리 부담은 제거
  - 이 결정에 따라 **휴식 방은 회복이 아닌 "증원" 방으로 재정의** (아래) — 2026-07-26 실제 명칭도 "증원 방"으로 통일 반영 완료

**군대 업그레이드 (2026-07-19 신규, §4-26 — 장군 경험치 대체)**:
- 군대 정보 UI에 [업그레이드] 버튼 추가. 군대별 독립적으로 0~+5단계 (`ArmyInstance.upgradeLevel`)
- 비용: **재화 소비**, 단계가 오를수록 증가 (초안 — config): `+1: 50 / +2: 100 / +3: 200 / +4: 350 / +5: 550`
- 효과: 실행할 때마다 해당 군대의 **장군 체력/공격력/방어력 + 유닛 체력/공격력/방어력**이 함께 상승 (초안 — config): 레벨당 기본값 대비 **+10%** (단순 가산, +5 기준 최대 +50%). 장군 치명타율·이동속도는 대상에서 제외(밸런스 초안)
- 표시: 군대 정보 UI에 현재 단계를 `+N` 형식으로 표시 (0단계는 표시 없음 또는 "+0")
- 이 결정으로 §9 "재화 사용처" 미결 항목이 상점 도입 전에도 일부 해결됨 (재화를 쓸 곳이 생김)

**유닛 수 표시 (2026-07-19 개정)**:
- 군대 정보 UI의 유닛 수 표시를 `현재/최대` 형식으로 개선 (기존엔 현재 수만 표시)
- 최대 유닛 수: `ArmyDefinition.maxSoldierCount` 필드 신규 — 초안값은 **`baseSoldierCount × 2`** (예: 기본 30명 → 최대 60명). 증원 방 효과(§5.5 아래)가 이 상한까지만 병사 수를 늘림 (군대 업그레이드는 병사 수가 아닌 스탯만 상승시키므로 이 상한과 무관)

**증원 방 (재정의 — 제안, 2026-07-26 "휴식 방"에서 개칭)**:
- 효과: 보유 군대 중 1개 선택 → 병사 수 영구 +20% (config)
- 대안(2차 검토): 아이템 1개 획득과 택일 제시
- ※ 병력 손실 모델이 바뀌면(§9 미결 참조) 회복 기능으로 환원 가능하도록 효과를 데이터로 정의

### 5.6 아이템 시스템

- **슬롯**: 부대당 1개. 이미 아이템이 있는 부대에는 부여 불가 (교체 없음 — 귀속)
- **데이터**: `ItemDefinition` (ScriptableObject)
  - 아이콘, 이름, 설명
  - 부여 시 병과 (`ArmyClass` enum: Archer, Warrior, Hunter, Assassin, …)
  - 스탯 보정값 (사거리, 이동속도, 공격력 등 — 인게임 협의 필드)
  - 예약 필드(1차 미사용): 카테고리, 선행 아이템 (점토병사식 확장 대비)
- **아이템 4종**: 활(→궁수)/검+방패(→전사)/도끼(→사냥꾼)/단검(→암살자) (2026-07-26 개정, §4-30 — 4병과 확장). 이후 점토병사 카테고리표([[사전 조사]] §2) 참고해 추가 확장
  - 코드 상 `ArmyClass.Cavalry`/`Spearman`은 미사용으로 격하(예약 유지). 기존 예약값 `ArmyClass.Shieldman`을 "전사"로 활성화(2026-07-19)했고, `Hunter`/`Assassin`을 신규 추가(2026-07-26)
- **장군 스킬 컨셉 초안** (§4-23 — 효과 수치는 인게임 조율):

| 아이템 | 병과 | 장군 스킬 (초안) | 컨셉 |
|--------|------|-----------------|------|
| 활 | 궁수 | 일제 사격 (Volley) | 범위 내 다수 적에게 원거리 일제 공격 |
| 검+방패 | 전사 | 도발 (Taunt) | 범위 내 적의 공격 대상을 자신에게 집중시키고 피해 감소, 아군 병사 보호 |
| 도끼 | 사냥꾼 | 강타 (Smash, 2026-07-26 초안) | 강한 일격으로 높은 단일 대상 피해 |
| 단검 | 암살자 | 기습 (Ambush, 2026-07-26 초안) | 크리티컬 확률 위주 차별화 — 공격력은 과하게 낮추지 않음(인게임 스탯 협의 필요) |
- **귀속 경고 팝업** (기획서 필수 요구):
  - 아이템을 부대에 드롭하는 순간 표시: "이 아이템은 부대에 귀속되며 되돌릴 수 없습니다"
  - [부여] / [취소] + **[다시 표시하지 않음] 체크박스**
  - 체크 시 PlayerPrefs에 영구 저장, 이후 팝업 생략하고 즉시 부여
  - 의도: 경고를 통한 자연스러운 메커니즘 학습 (기획서 명시)

**아이템 획득 경로 확장 — 전투 승리 드롭 (2026-07-19 신규, §4-28)**:
- 기존 경로(이벤트 방, §5.4)에 더해, **전투 승리 시 격파한 적 군대 구성에 따라 아이템 획득**
- 규칙: 승리한 전투의 적 군대 목록 중 **병과가 있는 군대(궁수/전사/사냥꾼/암살자 등)마다 개별로** 드롭 확률을 판정 → 성공 시 그 병과에 대응하는 아이템 1개 획득. 병과 없는(기본) 적 군대는 판정 없음
  - 예: 적 구성이 궁수 2 + 전사 1 + 기본 2일 때 → 궁수 2개, 전사 1개에 대해 각각 독립 판정. 궁수 2개는 성공, 전사는 실패면 **활 2개** 획득
- 드롭 확률 (초안 — config, `ItemDropConfig` 또는 `RoomEncounterTable`과 연동): **병과당 25%**
- 획득 연출: 기존 보상 플라이 연출(§5.8) 재사용
- 전제: 적 군대의 병과 구성 정보가 전투 종료 시점에 아웃게임에 있어야 함 — encounterId로 RoomEncounterTable을 조회하면 얻을 수 있으므로 §7 인터페이스(BattleResultData) 변경은 불필요. RoomEncounterTable 자체는 여전히 미결(§9)

**증강 시스템 (2026-07-19 신규, §4-27)**:
- **증강 방**: 신규 방 타입 (§5.3). 진입 시 증강 pool에서 3개를 무작위로 노출, 플레이어가 1개 선택 → 즉시 적용 후 그래프 복귀
- **효과 범위**: **런 전체 적용** — 선택한 증강은 즉시 보유 중인 대상 전체 + 이후 획득/부여되는 대상에도 영구 적용 (RunState에 선택한 증강 목록만 누적 저장). 아이템 증강은 해당 병과를 가진 군대(현재+이후)에만 적용, 스탯 증강은 보유한 모든 군대에 적용
- **pool 구성**: 아이템(병과)별 증강 3개 × 아이템 종류 수 + 공통 유닛 스탯 증강 3개. 1차(아이템 2종) 기준 `2×3 + 3 = 9`개 pool → 아이템이 늘어나면 pool도 함께 증가
- **데이터**: `AugmentDefinition` (ScriptableObject) — 아이콘, 이름, 설명, 종류(아이템 증강 | 스탯 증강), 아이템 증강이면 대상 `ArmyClass`, 효과 종류(장군 스킬 강화 | 유닛 스탯 증가), 효과 수치
- **1차 컨텐츠 초안** (효과 수치는 인게임 조율 전 가안):

| 구분 | 증강 (초안) | 효과 |
|------|------------|------|
| 궁수(활) | 일제 사격 강화 | 장군 스킬 Volley 동시 타격 대상 +1 |
| 궁수(활) | 궁수 공격력 증가 | 궁수 군대 유닛 공격력 +15% |
| 궁수(활) | 궁수 체력 증가 | 궁수 군대 유닛 체력 +15% |
| 전사(검+방패) | 도발 강화 | 장군 스킬 Taunt 범위 +20% |
| 전사(검+방패) | 전사 방어력 증가 | 전사 군대 유닛 방어력 +15% |
| 전사(검+방패) | 전사 체력 증가 | 전사 군대 유닛 체력 +15% |
| 공통 스탯 | 전군 공격력 증가 | 보유한 모든 군대 유닛 공격력 +10% |
| 공통 스탯 | 전군 체력 증가 | 보유한 모든 군대 유닛 체력 +10% |
| 공통 스탯 | 전군 방어력 증가 | 보유한 모든 군대 유닛 방어력 +10% |

> 사냥꾼(도끼)·암살자(단검) 전용 증강은 2026-07-26 기준 미콘텐츠 — 4병과 확장 후 위 궁수/전사와
> 동일한 3종(스킬 강화·방어력·체력, 또는 암살자는 크리티컬 확률) 패턴으로 추가 예정.

## 7. 인게임 인터페이스 (아웃게임 확정안)

인게임 개발자에게 전달하는 계약. **이 섹션이 곧 인터페이스 명세**이며 변경 시 양측 합의 필요.

### 7.1 아웃게임 → 인게임: `BattleSetupData`

```csharp
// OutGame.Logic — 직렬화 가능, Unity 타입 미사용
public class BattleSetupData
{
    public string roomId;              // 방 노드 ID
    public RoomType roomType;          // NormalBattle | Boss
    public string encounterId;         // RoomEncounterTable 키 (적 구성)
    public List<DeployedArmy> armies;  // 배치 결과

    // 캐릭터 선택 화면(§5.2.5)에서 고른 값 — 런 전체에 1번뿐이지만 armies와 같은 자리에서 매
    // 전투마다 다시 실어 보낸다. 스킬의 세부 효과는 인게임 스킬 시스템 책임이라 skillId만 넘긴다.
    public string playerCharacterId;
    public string playerCharacterSkillId;
}

public class DeployedArmy
{
    public string armyInstanceId;
    public string armyDefId;           // ArmyDefinition 키
    public ArmyClass armyClass;        // None | Archer | Warrior | Hunter | Assassin (Cavalry/Spearman은 미사용 예약, §4-25)
    public string equippedItemId;      // 없으면 null/empty
    public string generalSkillId;      // 병과 부여 시 장군 스킬 (§4-23, 없으면 null/empty)
    public int soldierCount;           // 증원 보정 반영된 최종 병사 수
    public int upgradeLevel;           // 군대 업그레이드 단계 (§4-26), 0~5 — 참고용(UI 배지 등). 아래 최종 스탯엔 이미 반영됨
    public int generalSkillUpgradeCount; // 장군 스킬 강화 증강(§4-27, GeneralSkillUpgrade)을 선택한 횟수

    // 최종 스탯(업그레이드+증강 배율이 이미 곱해진 값, 2026-07-26 확정) — 재계산 없이 그대로 사용
    public float generalHealth, generalAttack, generalDefense;
    public float generalCritRate, generalMoveSpeed;   // 배율 대상 아님, 원본 그대로. 유닛도 이 값 공유(§5.7)
    public float soldierHealth, soldierAttack, soldierDefense;

    public int slotId;                 // 배치 슬롯 ID
    public float slotX, slotY;         // 진영 내 정규화 좌표 (0~1), 아군 진영=좌측
}
```

**최종 스탯은 아웃게임이 이미 계산해서 넘긴다(2026-07-26 확정).** 처음엔 "`armyDefId`+`upgradeLevel`만 주고 인게임이 재계산"하는 방식을 검토했으나, 계산 로직(`ArmyStatCalculator`)이 두 곳에 흩어지면 어긋날 위험만 늘어난다는 이유로 폐기 — 아웃게임이 배치 확정 시점에 업그레이드(§4-26)+증강(§4-27) 배율을 전부 곱한 최종 수치를 `DeployedArmy`에 직접 담아 넘긴다. 인게임은 `ArmyDefinition`/`ArmyStatCalculator`를 몰라도 되고, 이 필드들을 그대로 전투 계산에 쓰면 된다. `armyDefId`/`upgradeLevel`은 재계산용이 아니라 순수 참고용(3D 모델 매핑, UI 배지 등)으로만 남겨뒀다.

**`generalSkillUpgradeCount`에 대해:** 장군 스킬 강화 증강은 정확히 무엇이 어떻게 강화되는지 아웃게임이 알지도, 계산하지도 않는다(§4-23과 동일 원칙 — 스킬 자체의 설계·구현은 인게임 책임). 그래서 "어떤 효과인지"는 넘기지 않고 **"몇 번 선택했는지" 횟수만** 넘긴다 — 이 부대(장군)의 병과에 적용되는 스킬 강화 증강을 몇 번 골랐는지(중복 선택/스택 허용, §4-27) 세어서 정수로 전달한다. 이 횟수를 스킬에 구체적으로 어떻게 반영할지(레벨업? 쿨다운 감소? 등)는 전적으로 인게임이 정한다.

**`playerCharacterId`/`playerCharacterSkillId`에 대해(2026-07-26 신규, §5.2.5):** 캐릭터 선택 화면에서 고른 플레이어 캐릭터와 그 캐릭터의 스킬 id다. `generalSkillUpgradeCount`와 같은 원칙 — 어떤 스킬을 쓸지 골랐다는 사실만 전달하고, 그 스킬이 실제로 무엇을 하는지·어떻게 발동하는지는 전적으로 인게임 스킬 시스템이 정의한다. 런 전체에 걸쳐 동일한 값이며, 전투마다 armies와 같은 자리에서 다시 실어 보낸다.

### 7.2 인게임 → 아웃게임: `BattleResultData`

```csharp
public class BattleResultData
{
    public string roomId;
    public bool victory;               // false → 아웃게임이 런 종료 처리
    // 예약(1차 미사용): 부대별 생존 수 — 병력 손실 모델 변경 대비
    public List<ArmySurvival> survivals;
}
```

### 7.3 호출 규약

- 아웃게임이 `BattleSetupData` 생성 → 정적 브릿지(`BattleBridge.StartBattle(setup, onResult)`)로 인게임 호출
- 인게임은 전투 종료 시 `onResult(BattleResultData)` 콜백 — 병력 손실 없음 모델이므로 1차에서 아웃게임은 `victory`만 소비. `survivals`는 모델 변경 대비 예약
- 씬 전환 방식(동일 씬 내 전환 vs 별도 씬)은 인게임 개발자 선택에 맡기되 콜백 계약은 유지. **별도 씬으로 전환하는 경우** 7.4의 핸드오프 절차를 쓴다.

### 7.4 씬 전환 핸드오프 (아웃게임/인게임이 다른 씬일 때, 2026-07-26 추가)

아웃게임(`InGame.unity`)과 인게임 전투 씬이 서로 다른 Unity 씬이라 `SceneManager.LoadScene`으로 전환해야 하는 경우의 표준 절차. **CSV/JSON 등 파일로 굽지 않는다** — 같은 프로세스·같은 Play 세션 안에서 씬만 바뀌는 것이므로, C# static 필드가 씬 로드를 거쳐도 그대로 살아있는 성질(도메인 리로드가 아닌 한)을 그대로 이용한다. `BattleBridge`는 이 목적의 정적 홀더 3종을 제공한다(`SetPendingBattle`/`ConsumePendingSetup`/`CompleteBattle`) — `BattleBridge` 자신은 `UnityEngine.SceneManagement`를 참조하지 않는다(EditMode 테스트 가능성 유지 목적). 실제 `SceneManager.LoadScene` 호출은 항상 이 브릿지를 쓰는 MonoBehaviour(양쪽 각자의 진입점) 쪽 책임이다.

**아웃게임 쪽 (`InGameFlowController` 등에서 1회 등록):**
```csharp
BattleBridge.Implementation = (setup, onResult) =>
{
    BattleBridge.SetPendingBattle(setup, onResult);
    SceneManager.LoadScene("Battle"); // 인게임 씬 이름 — 인게임 개발자가 정한 이름으로 교체
};
```

**인게임 쪽 (전투 씬의 부트스트랩 MonoBehaviour):**
```csharp
private void Start()
{
    BattleSetupData setup = BattleBridge.ConsumePendingSetup();
    if (setup == null)
    {
        // 씬을 단독으로 열어 테스트하는 중일 수 있음 — 더미 데이터로 대체하거나 조기 반환.
        return;
    }

    // setup.armies를 순회 — 각 DeployedArmy에 이미 최종 스탯이 담겨있으므로 재계산 없이 그대로
    // 3D 유닛 스폰 → 전투 진행
}

// 전투가 끝나면:
private void OnBattleEnded(bool victory)
{
    BattleBridge.CompleteBattle(new BattleResultData { roomId = currentRoomId, victory = victory });
    SceneManager.LoadScene("InGame"); // 아웃게임 씬으로 복귀
}
```

`ConsumePendingSetup()`은 꺼내가는 즉시 내부 상태를 비운다(다음 전투와 섞이지 않도록). `CompleteBattle()`도 콜백을 실행하고 나면 비우므로, 두 번 호출하면 `InvalidOperationException`이 난다 — 정상적인 흐름에서 전투당 정확히 한 번씩만 호출되게 하면 된다.
