# 적 데이터 연동 가이드 (인게임 개발자용, 2026-07-29)

아웃게임이 전투 시작 시 넘기는 `BattleSetupData`에 **적 진영 구성이 포함되도록 확정**됐다. 이
문서는 그 부분(`enemies`)과, 같이 넘어가는 **플레이어 캐릭터/스킬 선택 정보**, 그리고 양쪽이
공유할 수 있게 된 **씬 이름 상수**를 설명한다. 전체 계약은
[[상세 기획#7. 인게임 인터페이스 (아웃게임 확정안)]] §7을 참고 — 이 문서는 그중 위 세 가지의
사용법만 보충한다.

## 결론부터: `encounterId`로 뭔가 조회할 필요 없다

이전까지는 `BattleSetupData.encounterId`가 "적 구성을 조회하는 키"처럼 문서화돼 있었고, 그 조회를
수행할 `RoomEncounterTable`은 인게임 쪽이 만들 걸로 남겨져 있었다. 하지만 그 테이블은 실제로
만들어진 적이 없고, 같은 역할을 아웃게임의 `EnemyCompositionConfig`가 이미 하고 있었다 —
난이도 커브 카운터 기준으로 적 수·병과 구성·보스 구성을 정하는 로직이다.

**그래서 2026-07-29부터는 아웃게임이 그 결과를 직접 계산해서 `BattleSetupData.enemies`에 실어
보낸다.** 인게임은 이 리스트를 그대로 스폰에 쓰면 되고, `encounterId`는 로그·디버깅용 참고
식별자로만 남아 있다 — 조회 키가 아니다.

## `EnemyArmy` 필드

`Assets/OutGame/Scripts/Logic/Battle/EnemyArmy.cs` (`OutGame.Logic.Battle` 네임스페이스,
Unity 타입 미사용 — 순수 POCO라 인게임 프로젝트에 그대로 복사/참조 가능):

```csharp
public class EnemyArmy
{
    public string armyDefId;    // 아웃게임 ArmyDefinition 키 — 3D 모델/외형 매핑용 참고값
    public ArmyClass armyClass; // None | Archer | Warrior | Hunter | Assassin
    public int soldierCount;    // 스폰할 병사 수
}
```

- `armyDefId`: 지금은 `"army_basic"` 하나뿐이다(여러 종류로 늘어나면 그 값도 다양해짐). 아웃게임의
  스탯 밸런스에는 안 쓰이고, 인게임이 외형/모델을 고를 때 참고하라고 남겨둔 값이다.
- `armyClass`: 아군 쪽 `DeployedArmy.armyClass`와 완전히 같은 enum이다. `None`은 "기본(무병과)
  군대"를 뜻한다 — 실제로 존재하는 값이지 누락이 아니다.
- `soldierCount`: 그대로 스폰할 병사 수. 아군과 달리 증원/업그레이드/증강 보정이 없는 **순수 기본
  값**이다 — 적은 `RunState`에 저장되는 영구 자산이 아니라 이 전투 1회용으로 그때그때 생성된다.

## 아군(`DeployedArmy`)과의 차이

적 쪽은 아이템 장착, 장군 스킬, 업그레이드 단계, 증강 배율, 배치 슬롯 좌표가 전혀 없다 — 필드 자체가
없다. 즉:

| 아군(`DeployedArmy`) | 적(`EnemyArmy`) |
|---|---|
| `equippedItemId`, `generalSkillId` | 없음 (적은 아이템/장군 스킬 개념 자체가 없음) |
| `upgradeLevel`, `generalSkillUpgradeCount` | 없음 |
| 최종 스탯(`generalHealth` 등, 배율 이미 반영) | 없음 — 스탯은 인게임이 `armyClass`/밸런스 기획에 따라 직접 정의 |
| `slotId`/`slotX`/`slotY`(아웃게임이 배치 UI에서 결정한 좌표) | 없음 — 적 배치 위치는 전적으로 인게임 전투 로직 책임 |

정리하면: 아웃게임은 "**어떤 병과가 몇 명씩** 나오는지"만 확정해서 넘긴다. 그 적들의 실제 스탯,
AI, 배치 위치, 전투 중 행동은 전부 인게임이 결정한다 — 플레이어 쪽 `DeployedArmy`가 "최종 수치까지
아웃게임이 계산해서 넘기는" 것과는 반대되는 방향이니 혼동하지 말 것.

## 읽는 예시

```csharp
// 인게임 쪽 전투 씬 부트스트랩 (예시 — 실제 스폰 로직은 인게임 재량)
BattleSetupData setup = BattleBridge.ConsumePendingSetup();
foreach (EnemyArmy enemy in setup.enemies)
{
    // enemy.armyClass로 외형/유닛 프리팹 선택, enemy.soldierCount만큼 스폰.
    // 스탯(체력/공격력 등)은 인게임이 armyClass별로 자체 정의한 값을 사용한다.
    SpawnEnemyUnit(enemy.armyClass, enemy.soldierCount);
}
```

`setup.enemies`가 비어 있는 경우는 없다 — `DeploymentState.BuildSetup(...)`이 `enemyComposition`
파라미터를 null 검증하고, 전투/보스 방 진입 시 `InGameFlowController.OpenBattleRoom`이 항상 최소
1개 이상의 적 구성을 생성해서 넘긴다.

## 아직 안 넘어오는 것 (§9 미결)

- **적 버프**: 1차는 아웃게임 UI에 "없음"만 표시. 버프 시스템 자체가 아직 설계 전이라 `EnemyArmy`에
  버프 필드가 없다.
- **밸런스 수치**: `EnemyCompositionConfig`의 난이도 커브 구간(적 수·병과 가중치·보스 구성)은 초안
  값이다. 실제 체감 난이도는 인게임 전투 스탯이 정해진 뒤 함께 조율해야 한다.

이 두 가지는 데이터 전달 여부의 문제가 아니라 밸런스/설계 협의가 더 필요한 부분이라 별개로
남겨뒀다 — [[상세 기획]] §9 미결 항목 표 참고.

## 플레이어 캐릭터/스킬 정보

`BattleSetupData`에는 적 구성과 별개로 캐릭터 선택 화면(§5.2.5)에서 고른 값도 실려 있다:

```csharp
public string playerCharacterId;      // 고른 캐릭터 id (지금은 char_1~char_4 플레이스홀더)
public string playerCharacterSkillId; // 그 캐릭터의 스킬 id — 런 전체에 걸쳐 캐릭터당 정확히 1개
```

`armies`/`enemies`와 같은 자리에 있고, **전투마다(런 전체에 1번뿐인 값이어도) 매번 다시 실어
보낸다** — 별도의 "런 시작 시 1회 전달" 채널이 없다. 스킬 세부 효과(수치·발동 조건 등)는 아웃게임이
정의하지 않는다 — `DeployedArmy.generalSkillUpgradeCount`와 같은 원칙으로, "어떤 스킬을 골랐는지"만
전달하고 실제 구현은 인게임 몫이다.

**현재 상태(2026-07-29 확인): 이 두 필드는 아직 아무도 안 읽는다.** `PLAYER_SKILLS.md`에 문서화된
플레이어 스킬 4종(번개/독구름/힐 장판/전투 함성)은 어떤 캐릭터를 골랐든 상관없이 항상 전부 다
쓸 수 있게 인게임 자체적으로 구성되어 있고, `BattleSetupConverter.ToBattleRequest(...)`도
`BattleRequest`/`SquadRequest`도 이 값을 옮기지 않는다 — 캐릭터 선택은 지금 전투에 아무 영향이
없다. `PLAYER_SKILLS.md` §7에 인게임 쪽이 먼저 물어둔 대로("메타 진행에 스킬을 얹을 계획이 있으면
알려달라"), 나중에 캐릭터별로 쓸 수 있는 스킬을 제한/해금하는 식으로 연결하고 싶다면:

```csharp
// BattleSetupConverter.ToBattleRequest(...) 안에, 예시
request.playerSkillId = setup.playerCharacterSkillId; // BattleRequest에 필드 추가 필요
```

이 확장이 필요한 시점에 알려주면 아웃게임 쪽에서 계약을 더 바꿀 일은 없다 — 이미 넘어가고 있는
값을 인게임이 받아 쓰기만 하면 된다.

## 씬 이름 상수 (`SceneNames`)

메인메뉴/아웃게임/전투 씬을 오갈 때 양쪽이 각자 문자열 리터럴로 씬 이름을 하드코딩하면 한쪽이
씬 이름을 바꿔도(이번에 실제로 `InGame` → `OutGame`으로 바뀌었다) 조용히 어긋난다. 그래서
아웃게임의 씬 이름 상수 클래스를 인게임도 그대로 참조할 수 있게 옮겨뒀다:

```csharp
// Assets/OutGame/Scripts/Logic/Flow/SceneNames.cs — namespace OutGame.Flow
public static class SceneNames
{
    public const string MainMenu = "MainMenu";
    public const string OutGame = "OutGame";   // 2026-07-29부터: 맵선택/캐릭터선택/방그래프 통합 씬
    public const string Battle = "Battle";     // 인게임 전투 씬
}
```

`OutGame.Logic` 어셈블리 소속이라(2026-07-29 이동) `NHN.Integration`이 이미 참조하고 있는
`OutGame.Logic`을 통해 별도 어셈블리 참조 추가 없이 바로 쓸 수 있다:

```csharp
using OutGame.Flow;
// ...
SceneManager.LoadScene(SceneNames.Battle);
Scene outGameScene = SceneManager.GetSceneByName(SceneNames.OutGame); // 하드코딩 "InGame" 대신
```

특히 `BattleBridgeConnector.cs`의 복귀 대상 씬 이름 상수(`OutGameSceneName = "InGame"`)는 이번
씬 통합으로 실제 씬 이름이 `OutGame`으로 바뀌면서 더 이상 일치하지 않는다 — `SceneNames.OutGame`으로
바꿔 참조하면 이후 아웃게임 쪽에서 씬 이름이 또 바뀌어도 컴파일 타임에 잡힌다(문자열 리터럴이었으면
조용히 실패했을 부분).
